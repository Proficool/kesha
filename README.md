# Кеша — голосовой помощник для родителей

Очень лёгкое Android-приложение: человек нажимает одну большую кнопку, задаёт вопрос
голосом и получает ответ **текстом на экране и голосом**.

Вся «умная» часть живёт на сервере в n8n (воркфлоу «Иннокентий»). Приложение только
записывает голос, превращает его в текст, отправляет на сервер и озвучивает ответ —
никакой логики советов внутри нет.

Ориентир по размеру APK — **до 2,5 МБ**.

---

## Что внутри

| | |
|---|---|
| Платформа | нативный Android, Kotlin |
| Зависимости | **нет** (только стандартная библиотека Kotlin) |
| AndroidX / Compose / Retrofit / OkHttp | **не используются** |
| Интерфейс | целиком кодом, XML-разметки нет |
| minSdk | 21 (Android 5.0) |
| targetSdk / compileSdk | 35 |
| Разрешения | `INTERNET`, `RECORD_AUDIO`, `VIBRATE` |
| Распознавание речи | системный `SpeechRecognizer`, `ru-RU` |
| Синтез речи | системный `TextToSpeech`, `ru-RU` |
| Экранов | один |
| Хранение | `SharedPreferences` (`sessionId`) |

Распознавание и синтез — системные службы, поэтому в APK не попадает ни байта моделей,
ни библиотек. Приложение одинаково работает на любом процессоре и почти не ест память.

### Файлы

```
app/src/main/java/by/colesa/kesha/
├── MainActivity.kt    единственный экран: кнопка, состояния, разрешения, приветствие
├── KeshaUi.kt         весь интерфейс кодом: кнопка 240dp, ответ 30sp, цвета состояний
├── KeshaListener.kt   SpeechRecognizer под тихую речь с паузами
├── KeshaSpeaker.kt    TextToSpeech, проверка русского голоса
├── KeshaApi.kt        POST на вебхук через HttpURLConnection
└── KeshaHaptics.kt    вибрация в начале и конце записи
```

## Сборка

### В GitHub Actions

Workflow уже лежит в `.github/workflows/build.yml`:

1. залить репозиторий в GitHub;
2. при пуше в `main` (или вручную через *Run workflow*) сборка запускается сама;
3. готовый файл — в артефактах сборки, имя `kesha-debug-apk`.

Никакой настройки не требуется: Android SDK на раннерах GitHub уже установлен.

### Подпись — почему ключ лежит в репозитории

APK подписывается ключом `keystore/kesha-debug.p12`, который лежит в репозитории
вместе с паролем `kesha-debug`.

Это сделано не от лени. Раннер GitHub Actions одноразовый, и Gradle при каждом
запуске создавал **новый** отладочный ключ в `~/.android/debug.keystore`. Два
соседних билда из CI оказывались подписаны по-разному, и новый APK нельзя было
поставить поверх предыдущего: Android отказывал по несовпадению подписи, а на
телефоне оставалась старая версия. Именно на этом сломалась первая попытка
обновления.

С постоянным ключом сборка воспроизводима: локальная и CI дают **идентичный
файл**, и любой APK ставится поверх любого.

**Ключ публичный и годится только для отладки.** Для Google Play нужен отдельный
release-ключ, которого в репозитории быть не должно: его пароли уходят в
GitHub Secrets, а файл — нет.

### Локально

```bash
./build.sh          # debug, то же самое, что делает CI
./build.sh release  # release с R8 (пока без подписи)
./build.sh clean
```

Нужен JDK 17 и Android SDK (platform 35, build-tools 35.0.0). Скрипт ищет их в
`../.toolchain` — так устроена песочница, в которой проект создавался; при обычной
сборке достаточно, чтобы были выставлены `JAVA_HOME` и `ANDROID_HOME`.

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

## Как это работает

### Контракт сервера

```
POST https://n8n.microstoma.top/webhook/innokentiy
X-App-Token: <токен зашит в APK>
Content-Type: application/json

{"text": "...", "sessionId": "...", "lang": "ru"}
```

Ответ `{"status":"ok","answer":"..."}` — уже чистый текст без разметки, готовый и для
показа, и для озвучки. Таймаут на чтение — 60 секунд (ответ приходит за 2–3 секунды,
но запас нужен).

`sessionId` генерируется один раз при первом запуске и хранится в `SharedPreferences`.
По нему сервер помнит контекст разговора: второй вопрос учитывает первый.

### Состояния

Цвет большой кнопки однозначно говорит, что происходит:

| Цвет | Надпись | Что значит |
|---|---|---|
| серый | НАЖМИТЕ И ГОВОРИТЕ | ждём |
| пульсирующий красный | ГОВОРИТЕ | идёт запись |
| жёлтый | ДУМАЮ | запрос ушёл, ждём ответ 2–3 секунды |
| зелёный | ОТВЕЧАЮ | Кеша говорит |

### Речь пожилых людей

Запись не обрывается на первой паузе: `EXTRA_SPEECH_INPUT_COMPLETE_SILENCE_LENGTH_MILLIS`
= 2500 мс, `POSSIBLY_COMPLETE` = 1500 мс, минимальная длина фразы 3000 мс.
Промежуточный результат распознавания показывается на экране — человек видит, что его слышат.
Повторное нажатие кнопки во время записи означает «я закончил».

### Мужской голос

Иннокентий — мужчина, а системный синтезатор по умолчанию часто берёт женский голос.
Задать пол напрямую нельзя: **в Android у класса `Voice` нет признака пола**, а
`setLanguage("ru-RU")` выбирает голос по умолчанию, который задан в настройках телефона.

Поэтому приложение действует в два слоя:

1. Если среди русских голосов есть тот, у которого в имени или в списке признаков
   явно написано `male`/`female`, берётся мужской и читается своим естественным тоном.
2. Если пометки нет (обычный случай), голос телефона **не подменяется** — остаётся тот,
   что выбран в настройках синтезатора, — но тон понижается до `0.85`, чтобы голос
   звучал ниже.

Отдельного выбора голоса в приложении нет намеренно. Если на телефоне есть мужской
русский голос, самый надёжный путь — один раз выбрать его в системных настройках:
**Настройки → Система → Языки и ввод → Синтез речи → Google → русский язык**.
Приложение подхватит этот выбор самó, потому что не подменяет голос без пометки о поле.

В лог (`adb logcat -s Kesha`) при старте пишутся имена всех найденных русских голосов
и выбранный тон — этого достаточно, чтобы при необходимости прописать мужской голос
в коде точно. Ни распознанный вопрос, ни ответ в лог не попадают.

### Если чего-то нет

* **Нет Google-сервисов** — `SpeechRecognizer` не работает. Приложение говорит об этом
  голосом, а не молчит.
* **Нет русского голоса в синтезаторе** — появляется кнопка «Установить русский голос»,
  которая открывает системную установку голосовых данных.
* **Нет интернета** — голосом и текстом: «Нет интернета. Проверьте, пожалуйста, связь».
* **Android 9+** — используется только HTTPS; `usesCleartextTraffic="false"` выставлен явно,
  чтобы случайная замена адреса на `http://` сразу дала понятную ошибку, а не тихую поломку.

## Отступления от спецификации

Одно, и сознательное:

* **Добавлено разрешение `VIBRATE`.** Спецификация требует вибрацию при старте и конце
  записи (раздел 5), но при этом перечисляет только `INTERNET` и `RECORD_AUDIO`
  (раздел 4). Без `VIBRATE` вызов вибратора падает с `SecurityException`. Это
  *normal*-разрешение: диалога пользователю не показывают, спрашивать нечего,
  веса в APK оно не имеет. Если разрешения или вибромотора нет, приложение
  откатывается на штатный тактильный отклик `View.performHapticFeedback`.

* **В лог пишутся имена голосов синтезатора и переходы состояний.** Раздел 6.7
  запрещает логировать лишнее, и это соблюдено: ни распознанная речь, ни ответы
  Кеши, ни идентификатор сессии в лог не попадают. Пишутся только технические
  события — иначе поведение на чужом телефоне неотлаживаемо.

* **Запуск записи повторяется до подтверждения.** `SpeechRecognizer.startListening()`
  при ещё не подключённой службе молча ничего не делает — ни записи, ни ошибки.
  Приложение подключается к службе заранее и повторяет запуск, пока не придёт
  `onReadyForSpeech`, а после шести неудач честно сообщает, что микрофон не отвечает.

Всё остальное — по спецификации.

## Что нельзя проверить без телефона

Компиляцию, сборку, размер APK, разбор ответа сервера и логику состояний проверили.
А вот это — только живой человек с телефоном:

* качество распознавания тихой и невнятной речи;
* наличие и звучание русского голоса;
* удобство кнопки и читаемость шрифта;
* не раздражают ли 2–3 секунды ожидания.

Это главный риск сроков, а не код.
